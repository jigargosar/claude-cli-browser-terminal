Thinking

The user wants the reply pane to stay fast on long turns. The transcript is the source of truth, so the cache only has to survive one page session.

A Map keeps insertion order. That makes evicting the oldest entry a single delete on the first key.

I should measure before adding eviction. A long reply may be slow for reasons the cache does not touch.

Plan for the cache

The cache holds the last 50 replies in memory. A refresh drops it, which matches Decision 2.2. The right panel may be blank after a refresh.

  1. Keep replies in a Map keyed by message id.
  2. Evict the oldest entry once the map passes 50.
  3. Write nothing to disk. The transcript already holds every reply.

Two risks remain. A very long reply may be slow to render. A rewind leaves stale entries behind.

Rendering is the bigger risk. Most replies are short, but a few run past 200 lines. Those few are the ones you read most closely.

How a lookup works

The page asks the cache for a message id. A hit returns the rendered node at once. A miss renders the markdown and stores the result.

const cache = new Map();
const lookup = (id, text) => {
  if (cache.has(id)) return cache.get(id);
  const node = render(text);
  cache.set(id, node);
  return node;
};

Each line of the code block above counts as one sentence. You can comment on a single line.

Eviction

Eviction runs after each insert. When the map passes 50 entries, the first key goes. Map iteration order makes that key the oldest.

A rewind is the hard case. The transcript drops entries, but the cache still holds their nodes. Those nodes never show again, so they only cost memory.

  • Option one: clear the whole cache on a rewind. It is simple and always correct.
  • Option two: drop only the entries after the rewind point. It keeps more hits, but it needs the rewind point.
  • Option three: ignore it. The 50-entry limit pushes stale nodes out within a few turns.

I lean toward option three. It needs no code, and the cost is bounded.

Open question: should a rewind clear the whole cache, or only the entries after the rewind point?

Measuring

I'll time a 200-line reply with and without the cache. The number decides whether eviction is worth its code.

If the uncached render is under 16 ms, the cache is not needed at all. If it is above 50 ms, the cache should ship with eviction.

I'll add the map first. Then I'll measure a long reply before adding eviction.
